# Exchange

Exports of the design to files other programs read. Milestone 9 grows it step by step: the plan drawing as DXF, SVG and PDF, the building as glTF and PNG renders (now), the DXF import (to come).

## What it does

- **`export.plan`** turns each requested level into a plan drawing (`planDrawing` in `packages/core/src/exchange/drawing.ts`: layered strokes, fills and texts in millimetres, from the same derived geometry the canvas draws) with the display units and rule limits from Settings, then writes it with one of the pure writers in core:
  - **DXF** (`drawingToDxf`): AutoCAD R2000, millimetres, one CAD layer per drawing layer; one file per level.
  - **SVG** (`drawingToSvg`): one self-contained document per level, on a paper sheet (A4, A3, A2, A1, Letter or Tabloid, portrait or landscape; A3 landscape by default) at 1:`scale`, in paper millimetres so it prints to scale, one `<g>` per drawing layer named after it, arcs as `A` commands, texts upright, a title block (project, level, scale, date).
  - **PDF** (`drawingToPdf`): one file with a page per level, a hand-written PDF 1.4 (no dependency): true vectors, arcs as Béziers, tints through an ExtGState alpha, texts in the standard Helvetica (WinAnsi), the same title block; content streams compressed with node's `deflateSync`.
- **`export.building`** writes the building in 3D as one self-contained GLB (`buildingToGlb` in `packages/core/src/exchange/gltf.ts`): metres with y up as glTF requires, a root node named after the project, a node per level named after it with a node per kind of solid, a node per connector starting on it (`Stair`, `Elevator` ...) and a node per furniture item named after its model, placed by its 4 × 4 matrix. Colours are the 3D view's (materials' colour, roughness, metalness and opacity, paints, glass see-through and double-sided); patterns are written as their plain colour, lights are not written. Imported models are read from the project's `assets/` through `host.projects.readAsset` (registered files only) and embedded; one whose file is missing is left out and listed in `skipped`.
- **`export.image`** writes a PNG render: the window draws it the way `view.snapshot` does (main has no canvas; `requestSnapshot` from the plan module emits `view.snapshot.request` with the size, the theme and `transparent`, and waits up to 60 s for the hidden `view.snapshot.reply`), then the module checks the PNG's IHDR against the size asked for (`checkedPng`, with `readPngHeader` from `packages/core/src/exchange/png.ts`) and writes it. A plan in the light or dark palette, or with no paper at all; the building in 3D with the 3D view's options, its canvas cleared to alpha 0 without a sky when transparent. **4096 × 4096 in 3D:** the WebGL drawing buffer is capped by the GPU; when Chromium gives a smaller buffer than asked for, `renderBuildingToPng` throws and the command fails with `UNAVAILABLE` naming the size it could draw, and nothing is written; a smaller image is never returned (the IHDR check in main refuses one too). The smoke accepts either outcome at 4096 × 4096 and logs which.
- With several levels, DXF and SVG put the level's name before the extension (`Plan - Ground floor.svg`, numbered when two names clash); PDF writes the one path. `fit` (SVG and PDF) picks, per level, the largest of 1:20, 1:25, 1:50, 1:100, 1:200, 1:250, 1:500 and 1:1000 that fits inside the 10 mm margin above the title block.
- After writing, the module announces `exchange.exported { projectId, format, files }` (`format` is `dxf`, `svg`, `pdf`, `glb` or `png`).
- Files are written with `writeFileAtomic` (the folder is created when missing). Paths must be absolute.

## Storage

Nothing in the library: the files go where `path` says. The project is only read.

## Agents

`export.plan` (**gated**: it writes outside the library, so MCP agents are refused with `MUTATION_BLOCKED` until the user allows mutations in Settings, and the in-app assistant asks first). Input: `path` (full file path), `format` (`dxf` | `svg` | `pdf`), `levelIds` (default every level, bottom to top), `scale` (1:N, default 100), `page` (default `A3`), `orientation` (default `landscape`), `fit`, `layers` (drawing layer kinds; default all), `title` (default true). Returns `{ format, files: [{ path, levelId?, bytes }], levels: [{ levelId, name, scale }] }`.

`export.building` (**gated** likewise). Input: `path` (full file path), `levelIds` (default every level; a connector goes with the level it starts on), `includeItems` (default true), `includeFinishes` (default true). Returns `{ path, bytes, nodes, triangles, skipped }`.

`export.image` (**gated** likewise; needs the app window, like `view.snapshot`). Input: `path` (full file path), `levelId` (default the ground level), `view` (`plan` | `3d`, default `plan`), `width` and `height` (integers 64 to 4096, default 1600 × 1200), `azimuth` (default 225), `elevation` (default 30), `display` (`all` | `isolate` | `cutaway`), `explode` (0 to 1), `lighting` (`day` | `night`), `theme` (`light` | `dark`, default `light`), `transparent` (default false). Returns `{ path, bytes, width, height, view, levelId, levelName }` (not the image: `view.snapshot` is for looking). Fails with `UNAVAILABLE` when no window draws it within 60 s or it cannot be drawn that large, `NOT_FOUND` for an unknown level or nothing to draw, `INVALID_INPUT` for a relative path.
