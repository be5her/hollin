# Edit

Changes, undo and redo, and how the renderer follows the document.

- **Every edit is a transaction:** a set of changes to records (levels, layers, entities, connectors, the building) applied to a copy-on-write draft and committed all at once or not at all. Commit validates every touched record against its schema and checks the references between records (an entity's layer is on its level and of the right kind, an opening's wall exists, nothing points at something removed, the level stack is consistent). Hard rules reject the change; soft problems (a corner that does not fit) are reported, not refused.
- **History:** one linear stack per open project, shared by you, the assistant and agents, because undoing strictly newest-first keeps every inverse valid. Each step has a label and an author (`{ kind, name }`: you, the assistant with its model id or `claude-code <version>`, or an MCP agent with the name its client reports), the command that made it (`command`, the outermost one: `plan.apply` for a batch; the registry puts it in the command context and `editProject` passes it on), and the one level and layer its entities share, when they share one (`levelId`, `level`, `layer`). The History panel (`design/identity/03-otto.md` §d) signs each row: yours "You · <layer>" with a graphite dot; Otto's (author kind `assistant`) "Otto · <layer> · <command id>" on `--ai-tint` with the 16 px mark and the meta text in `--fg` at 70 %; an MCP agent's "MCP · <client> · <layer> · <command id>" with a hollow ring. The newest row, the one Ctrl+Z takes, carries a 2 px terracotta bar. While Otto waits for your yes on a destructive call, that call sits greyed at the top ("Otto · waiting for your yes"; from `AppState.assistant`, not an undo step) until you answer. Clicking a row (or Enter on it) selects on the plan what that step added or changed, switching to its level first (`edit.history.changed` gives the ids and the level, `PlanSelection.request` selects them, as the Warnings panel does; a step that touched connectors only selects on the level on screen); double-clicking a row undoes down to it, one `edit.undo` with `ifTop` per step, so a change that lands meanwhile stops it and redo brings every step back. Rapid edits to the same thing (an opacity slider, a height being nudged) merge into one step, whose level and layer are worked out again from what the merged step touches. The stack keeps 500 steps and about 64 MB. Undo and redo do not survive closing a project; the first edit of each session therefore keeps the project as it was in an automatic snapshot. Restoring a snapshot replaces the document and starts a fresh history.
- **Ctrl+Z, Ctrl+Shift+Z and Ctrl+Y** undo and redo the design, except while a text field has focus (it keeps its own undo). The project tab has Undo and Redo buttons naming the change; the History panel lists every step with its author.
- **The live mirror:** the document lives in the main process. After every change the host broadcasts `doc.patched` with the change number, the epoch and the net changes per record; the renderer applies them with the same code (`applyPatch`). Patches arriving while the document loads are replayed after it; a gap in the numbers or a new epoch makes the renderer fetch the whole document again. So edits by agents appear at once.

## Agents

- Allowed: `edit.undo` (with `ifTop`, it undoes only if that change is still the newest, so an agent never undoes the user's work by accident), `edit.redo`, `edit.history`.
- Not exposed: `doc.get` (the whole document, for the renderer), `project.ui.get/set` (view state), `edit.history.changed` (read-only: the ids and level a History row selects).
