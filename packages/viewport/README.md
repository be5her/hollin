# @studio/viewport

Framework-free renderers driven by the document. `plan2d` draws and edits one level from above on a Canvas 2D; `scene3d` (three) arrives with milestone 7. The package is imported by the renderer only; main never loads it.

## plan2d

| File | What |
|---|---|
| `camera.ts` | The camera (`{ x, y, scale }`: the world point at the canvas centre in mm and the zoom in CSS pixels per mm), world ↔ screen mapping (the world is y-up, the screen y-down), zoom about a point, pan, fit to a box, the `1:N` drawing scale. |
| `theme.ts` | The colours the plan is drawn with, read from the CSS variables in `styles.css` (`--plan-*`, `--canvas`, `--fg` …) so the canvas follows the theme. |
| `scene.ts` | A level's entities in an R-tree (`rbush`), with a generous world box per entity type. `syncLevelScene` diffs by object identity: the mirror keeps untouched entities' objects through patches, so only changed entities are rebuilt. An opening follows its wall. |
| `draw.ts` | Tracing paths (lines, arcs by bulge, cubics) onto a `Path2D` or a context. |
| `render.ts` | One frame: background, the adaptive grid (minor and major lines by zoom, metric or imperial), the reference level faintly, then the entities in a fixed order (slab, rooms, voids, walls, columns, openings, fixtures, dimensions, labels), culled by the visible box, then text in screen space. `Path2D` outlines are cached per entity and refilled, so panning and zooming never rebuild geometry. |
| `geometry-cache.ts` | Wall bodies, a level's joined walls (with exclusions for drag previews) and the whole level geometry (rooms, cavities, the slab) memoised by object identity (valid in the renderer only; see CLAUDE.md). The plan view and the Properties panel share one cache. |
| `hit.ts` | What is under a point: candidates from the R-tree, then an exact test per type (wall bodies, opening cuts, column footprints, regions, filled shapes anywhere inside and outlines or open lines along them, glyphs, dimension lines, label boxes), ranked smallest first (a door before its wall before a shape before the room). Hidden and locked layers are skipped. Window and crossing marquees by entity boxes. |
| `grips.ts` | The grips of a selected entity (its path's vertices and segment middles, holes included, and a corner grip on each fillet or chamfer between straight edges, placed by `cornerFrame`/`cornerGripPoint` from core), which one is under a screen point, and the `VertexRef` the inspector edits. |
| `snap.ts` | Snapping: a `SnapIndex` (an R-tree of everything on the level a point can snap to: wall reference lines and faces, region and shape outlines, dividers, opening jambs, centres) and `snapPoint`, which ranks candidates within a tolerance by kind (endpoint, intersection, midpoint, centre, perpendicular or tangent from a start point, on a line, extension, angle step) then distance, with the grid as the fallback and Shift as a 45° constraint. Pure and unit-tested. |
| `tools/` | The tools as state machines fed pointer and key events, drawing their previews and committing through commands: `select.ts` (click, Shift, marquees, drag-move with the walls joined live, Ctrl-copy, nudges, Delete, Ctrl+A/C/V/D, rotate about a pivot, mirror across two points; grip drags that move a vertex with the wall ends that meet it, curve a segment through the cursor or split it, select a corner, F/C corners, size a corner by its grip or a typed length) `wall.ts` (runs of walls, arcs, closing) `opening.ts` (doors and windows placed where the cursor projects on a hovered wall, moved into the nearest free gap, a typed distance from the wall start, flips while placing), `room.ts` (the enclosed space under the cursor lit up with its area, a click makes it a room), `separator.ts` (room divider lines) and `shape.ts` (one class, three tools: a polyline with arcs, closed on its first point or with `C`, a rectangle from two corners, a circle from its centre and a point; what the outline makes is an option: a free shape, or a room, slab or void region, always closed and counter-clockwise). `tool.ts` is the contract: a `ToolHost` gives a tool commands, the entities, the mirror's change number for stale checks, the selection and the selected vertex, hit-testing and the joined walls. |
| `editor.ts` | `Plan2dEditor`: attach to a canvas, feed it the document, the active level, the underlay mode, the theme, the units and the tool options; it keeps a scene for the active level and the reference level only, owns the selection (pruned on every document change) and the clipboard, renders at most once per animation frame (`invalidate()`), and handles the mouse and keyboard: wheel zooms at the cursor, middle-drag or Space+drag pans, Home fits, PageUp/PageDown ask the host to change level, V, W, D, N, R, S, P, K and O pick tools, Escape cancels. A digit typed while a tool waits for a point asks the host to open an input at the cursor; `typed(text)` parses the coordinate grammar and hands the point to the tool. Callbacks report the camera, the cursor, the snap, the tool and its hint, the selection and the selected vertex, a right click, and frame statistics. |

The Angular host (`packages/modules/plan/ui/plan-view.ts`) owns the canvas element, sizes it with a `ResizeObserver` times `devicePixelRatio`, re-reads the theme when `<html class>` changes, persists the camera and mirrors the editor's state into `data-camera="x,y,scale"`, `data-level`, `data-underlay`, `data-entities` and `data-frame-ms` attributes on the canvas, which the smoke test reads to convert millimetres to window pixels and to assert without any globals.

## Dependencies and why

| Package | Why |
|---|---|
| `rbush` 4 | An R-tree for culling what is drawn and for hit-testing candidates. ESM, so the Angular build raises no CommonJS warning; it ships no types, hence `@types/rbush` at the root. |

## Tests

`npm test` runs `*.test.ts` here in node: the camera mapping and zoom, the scene index (boxes per type, diffing, openings following walls) and the editor without a canvas (scenes per level, underlay choice, fit, camera callbacks). Nothing here touches `ResizeObserver`, `OffscreenCanvas` or `Path2D` at import time; `Path2D` outlines are built lazily at draw time. Drawing itself is checked by the smoke test (`src/main/smoke/plan-ui.ts`), which samples canvas pixels and takes screenshots.
