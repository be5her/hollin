# Milestone 11: review

A review of every change since `26c8165` (the six milestone-11 commits, `2d9f9be` to `03599ec`, read as one diff) against the identity documents they build (`design/identity/00-decisions.md`, `01-brand.md`, `03-otto.md`, `04-canvas.md`, `06-open-points.md`) for correctness, the smoke's coverage and the documentation's accuracy, plus the exports read by programs the app did not write and the packaged build's smoke. Fixed in `Milestone 11: review fixes`.

## Findings

1. **(medium) The bundled fonts were never proven to load.** Every check that read a computed `font-family` passes whether or not the face loaded (the family name is in the stack either way), so a font missing from the packaged `out/renderer/media` would have gone unnoticed. **Fixed:** a new first section of `identity-ui.ts` waits for `document.fonts.ready`, asks for each face (`document.fonts.load`) and checks that `document.fonts.check('12px "<family>"')` holds for Alegreya Sans, IBM Plex Mono and Fraunces and that each has a declared face in the `loaded` state and none in `error` (`check` alone is true for a family no face is declared for). It passes in `npm run smoke` and in the packaged build (see Verification), which loads the faces over `file://`.
2. **(medium) The SVG title block's full stop floated.** The wordmark was two `<text>` runs, the name and a terracotta `.` placed after it at the name's width measured in Helvetica Bold; a reader that draws the sans stack in Alegreya Sans (or any font but Helvetica) put the stop in the wrong place, off the name or into it. **Fixed:** the SVG writes the wordmark as one `<text>` with `<tspan fill="#b9552f">.</tspan>`, so the stop follows the name in whatever font draws it; the PDF, which embeds no font and draws Helvetica Bold, keeps the two measured runs (`TitleBlockText.stop` marks the stop). `svg.test.ts` checks the one text with its tspan; the smoke's SVG check looks for it.
3. **(medium) Undoing Otto's entry marked the project as Otto's work again.** `ProjectService` set `assistantUnsaved` on every transaction authored by the assistant other than `meta` and `replace`, undo included, so undoing Otto's edit moved the library's `assistantEditedAt` to the time of the undo. **Fixed:** only `do` and `redo` transactions by the assistant mark the project. `library.test.ts` undoes Otto's edit and checks the stamp unchanged after the save, then redoes it and checks the stamp moved.
4. **(medium) First launch's Otto line was static text,** where `03-otto.md` §g asks for the empty project's editable sentence that Enter sends like Draft it. **Fixed:** `first-launch.ts` has the same line as the empty level's guide ("Or tell Otto:", the editable sentence pre-filled with "a 5 by 7 m studio with a bathroom in the corner", the same borderless input on the tint); Enter goes through `OttoDraftRun.start`, which `OttoComposer.draft` now shares (project created and named from the sentence, opened with the Otto tab showing, the sentence sent, or offered to the panel when the send is refused). Without a ready provider the line says "Or tell Otto, once it has a key:" and Enter opens Settings > Assistant. Smoke: on the first-launch library, with a key, the line holds the sentence, Enter on an edited one creates a project with it as its description, the sentence is the chat's first message and the fake API's reply shows; that project goes to the trash before the others are restored. Library README and `CHANGELOG.md`.
5. **(low) A merged (coalesced) history step kept the first step's level and layer.** The coalesce branch spread `top` and then `whereOf(...)`, which omits a key when the merged step spans several levels or layers, so the stale `levelId`, `level` and `layer` survived. **Fixed:** they are dropped from `top` before the spread. `doc.test.ts`: two coalesced labels on two levels give one step naming no level or layer.
6. **(low) A failed Claude Code probe left an unhandled rejection:** `void status.finally(...)` returns a promise that rejects with the probe. **Fixed:** `.catch(() => {})` on that chain; the caller still sees the failure through `status`.
7. **(low) A batch's pending outline marked steps that delete nothing.** `targetIdsOf` read the ids of every step of a `plan.apply` input. **Fixed:** it reads only the steps whose command its `isTarget` accepts (none without it); `OttoPresence` passes the command the confirmation names. In practice the registry asks for each mutating step on its own, so a confirmation's input is that step's; the rule keeps a batch input from outlining its other edits. `assistant-targets.test.ts`: a batch of an update, a delete and a transform outlines only the deleted wall; no test, no ids; malformed steps skipped.
8. **(low) The canvas tag's typography:** mono 11 px in a 22 px pill, where `03-otto.md` §c and `01-brand.md` §d give the sans at 500, 12/24, padding 0 10 px 0 6 px, the glyph at 14 px. **Fixed** in `render.ts` (the glyph's square and pen dot redrawn in a 14 px box, centred). The smoke's tag check also checks its height, 24 px. Viewport README.
9. **(low) The glTF writer's `FALLBACK` was the old grey `#b8b4ac`.** **Fixed:** the palette's stand-in `#a69b8e`, exported as `SOLID_FALLBACK` (also the fallback of `srgbToLinear`); `snapshot-theme.test.ts` pins it to `--scene-stand-in` in `:root`.
10. **(low) A draft offer outlived its project.** `AssistantDrafts` kept an offer whose project closed before its panel took it, and the panel would take it when the project was opened later. **Fixed:** the offer is dropped on `project.changed` `closed` for its project. Unit test `assistant-drafts.test.ts`.
11. **(low) The empty level's guide depended on what the last frame drew.** `levelEmpty` read the frame's connector count, which counts only connectors drawn in view: a stair panned off-screen on an otherwise empty level brought "Draw the first wall." back. **Fixed:** it reads the document (the level's entities, and `connectorsOnLevel`, every connector that starts, ends or passes there).
12. **(nit) The guide's key cap said `Ctrl K` on every platform.** **Fixed:** `host.modKey`, as the title bar does (`⌘` on a Mac).
13. **(nit) About's "with Otto" was not italic** (`03-otto.md` §g: display 600 italic `--ai`). **Fixed;** the smoke's credit check also reads its `font-style`.
14. **(low) History rows did nothing when clicked** (`03-otto.md` §d: click selects what the entry changed, double-click undoes down to it). **Fixed, both:** the engine's `changed(txId)` gives the entity and connector ids an entry added or changed and its level (the entry's one level, else the level of the first entity, null for connectors alone), through the hidden read-only `edit.history.changed`; a click (or Enter on a focused row) switches to that level and asks `PlanSelection.request`, as the Warnings panel does. A double-click undoes newest first down to the entry, each `edit.undo` with `ifTop`, so a change landing meanwhile stops it and redo brings every step back; no engine support was needed beyond `changed`. Rows hover in `--elevated` (yours) or the tint mixed with `--elevated` (Otto's). Smoke in `otto-ui.ts`: clicking Otto's row selects its wall; double-clicking it undoes your newer wall and then Otto's (two redo rows); two redos bring both back. Edit README and `CHANGELOG.md`.
15. **(low) Thumbnails did not wait for the fonts.** `writeThumbnail` drew at once, so a thumbnail made before the faces had loaded (the first 1.5 s after opening a project, or leaving its tab) had its labels in system fonts. **Fixed:** it awaits the same `document.fonts.load` of the sans and the mono that the snapshot responder awaits, with everything it draws taken first (the view can be gone by then).
16. **(low) Two waits were unchecked.** `identity-ui.ts`'s wait for the studio chat to be idle and `otto-ui.ts`'s `idle()` returned false on a timeout and the section went on. **Fixed:** both are `smoke.check`s (`idle(when)` names the step it guards).
17. **(nit) `CLAUDE.md` gave the identity's shots as 64 to 67;** the files use 64 to 73. **Fixed** (64 to 67, 72 and 73 in `identity-ui.ts`, 68 to 71 in `otto-ui.ts`).
18. **(low) `OttoEdits` had no unit test.** **Added** `packages/ui/src/state/otto-edits.test.ts` with a fake `HostBridge` (the service built with `Injector.create` and `runInInjectionContext`, which runs in node without the Angular compiler): only Otto's added or changed ids are kept (not removed ones, not layers, not yours or an agent's), an undo removes the edit and a redo brings it back with its first age (gone a minute after it first landed), the minute's fade, your or an agent's next edit clearing them over 200 ms, a coalesced step merging its ids, `meta` ignored, `replace` and a closed project forgetting everything.
19. **(accepted) The wordmark is live text, not outlined paths.** The reviewer noted that `06-open-points.md` asked for the real font to be outlined before shipping. **Accepted as the decision:** Fraunces is bundled, live text is sharper at every size and follows `BRANDING.productName`, so the rename needs no new artwork. Recorded in `00-decisions.md` §6a; the open point is struck through. No code change.

## Leftover temporary folders

`%TEMP%` held 232 `studio-smoke-*` folders (from 6 Oct; 18 of them from 31 Oct, the six milestone steps each running the smoke more than once). **217 held only Chromium's own profile files** (`Local Storage`, `Session Storage`, `Network`, `Shared Dictionary`, `DIPS`, `declarative_performance_observer.db`), no `Library` and no settings: the smoke's `fs.rm` at the end had run and removed what the app wrote, but Chromium keeps those files open while the process lives (the network service holds `Network Persistent State` and `Trust Tokens`, the storage service the LevelDB locks) and writes some of them on the way out, so on Windows a folder of them was left after every run, the `.catch(() => {})` hiding the failure. **15 also held `Library`**: runs that never reached the cleanup (killed by PID as stale, or crashed before `runSmoke` returned).

**Fixed** for the first case: after its own `fs.rm`, the smoke starts a detached helper (`src/main/smoke/cleanup.ts`): the app's own executable as Node (`ELECTRON_RUN_AS_NODE`, as the fake Claude Code runs), which waits until the smoke's process is gone (60 s at most), a second more for Chromium's helpers, then removes the folder with retries; it is handed only a `studio-smoke-*` folder directly in the temp folder. Checked: four `npm run smoke` runs and the packaged smoke left no new folder. A killed run still leaves its folder (nothing of it runs to clean up); the existing folders were left as they were.
