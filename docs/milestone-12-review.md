# Milestone 12 review

Three read-only reviews of `git diff origin/main..HEAD` (ten commits, 287 files) after step 8: the engine and the main process, the renderer and the viewport, and a proofread of every Arabic string against its English. None found a high-severity defect. This file lists what they found, what was decided, and (under each item, once fixed) what was done.

Severity: **M** a bug a user can reach, **L** robustness, polish or a test gap.

## A. Engine and main

- **A1 (M) `latinKey` and shifted letters on the Arabic (101) layout.** `packages/core/src/i18n/keys.ts` returns any ASCII punctuation as it is, but on Arabic 101 Shift+L gives `/`, Shift+Z `~`, Shift+D `]`, Shift+F `[`, Shift+C `}`, Shift+V `{`: Shift+L never arms the Ladder and Ctrl+Shift+Z never redoes. **Decision:** when `code` is `Key[A-Z]`, Shift is held and `key` is ASCII punctuation, return the upper-case letter from `code`. Tests for these keys.
- **A2 (M) `latinKey` and AltGr.** A Latin letter with a diacritic (ń, ł, ż on Polish, Hungarian, Croatian layouts) is remapped through `code`; AltGr reports Ctrl+Alt on Windows, so typing ń in any text field runs New project, ł opens the palette. Before the branch `event.key` was `ń` and nothing happened. **Decision:** a key that is a Latin-script letter (`\p{Script=Latin}`) is returned unchanged, and nothing is remapped while Ctrl and Alt are both held (AltGr). Tests for both.
- **A3 (L) Text agents read that follows the interface language.** (a) `decor/items.ts` names a lost model `t('decor.missingModel')`, which reaches `plan.describe` and the glTF export; (b) `node/library.ts` `syncedFolderWarning` returns translated text in `library.info`; (c) `decor/main.ts` names a lamp's light `${name} light` in English in every language. **Decision:** (a) the name stays English in core and is translated where it is drawn; (b) English text plus a phrase, as `McpStatus` and `UpdateState` do, the renderer translating; (c) a default name through `t()` like the others. History labels and default names written while the interface is Arabic stay Arabic for every caller: they are the document's content, in the user's language, and Otto is told to write them so. `docs/i18n.md` says so plainly, as the one place agents read the user's language.
- **A4 (L) The English system prompt's live part gained the language line.** The stable prefix is byte-identical and cached; the live context now always ends with the language sentences, and the Claude Code `<app-context>` preamble was reworded. **Decision:** keep (a switch from Arabic back to English has to be told), and say so in the assistant README and `docs/i18n.md` as the exception to "English prompts unchanged".
- **A5 (L) `textDirection` misreads `×`, `÷` and Arabic-Indic digits.** `4 × 5 غرفة` reads `ltr`, `٣٦٠٠ mm` reads `rtl`. **Decision:** take U+00D7 and U+00F7 out of the Latin range and the Arabic-Indic and Persian digits and separators out of the right-to-left one. Tests.
- **A6 (L) A damaged font file surfaces as INTERNAL,** and a hostile format 12 `cmap` can loop for a long time. **Decision:** `readTrueType` checks the table directory and bounds the `cmap` groups by the table's length; `pdf.ts` turns a font that cannot be read into the translated `errors.exchange.noArabicFont`. The error's wording covers any text the standard fonts cannot write (Hebrew reaches it too). Tests with a truncated file.
- **A7 (L) Spreads over long strings in `arabic-shape.ts`** overflow the stack at about 150,000 code points. **Decision:** loops.
- **A8 (L) Arabic-script letters outside the shaping table** (U+0620, U+063B–063F, U+066E–066F, U+06AD, U+06C6 and others) break their neighbours' joining. **Decision:** joining types from Unicode's ArabicShaping for the whole Arabic block, even where no presentation form exists. Tests.
- **A9 (L) A non-integer comfort limit prints rounded** (`600.25` as `600.3`), which changes English wording for hand-edited limits. **Decision:** print the value as before the branch.
- **A10 (L) Tests.** "fills placeholders and leaves unknown ones alone" asserts neither; add them.

## B. Renderer and viewport

- **B1 (M) `type="number"` fields drop Arabic-Indic digits** (confirmed in Electron: the characters never reach the value): the PNG width and height in the export dialog, the DXF import's scale and origin, the MCP port in Settings. **Decision:** `type="text" inputmode="decimal"` (`numeric` for the port), `dir="ltr"`, parsed through `toLatinDigits`, with the same validation and messages as now. Check every other `type="number"` in the app the same way. A smoke check types Arabic-Indic digits into one of them.
- **B2 (M) English dates and times became US-formatted.** `intlLocale('en')` returns `'en'`, where the app used the OS locale (an en-GB user saw `14:05:03`). **Decision:** English passes `undefined` (the OS's format), Arabic keeps `ar-u-nu-latn`. Test.
- **B3 (L) Otto's replies lost their blank lines** on screen (several collapse into one short gap) and when copied, and every streamed chunk re-splits the whole conversation. **Decision:** a blank line is a line (an empty block of one line's height), so the text looks and copies as written; blocks are computed per item and cached by item id and text.
- **B4 (L) The Otto header changed in English:** the model name now truncates and the rule always shows. **Decision:** English renders exactly as on `origin/main` (compare `29-assistant-chat-light.png` with the same shot from `origin/main`'s smoke if in doubt); the Arabic fix (the rule never cut) stays, by a layout that gives the same result as before whenever everything fits.
- **B5 (L) A toast's close button is pushed out by a long path** (`161-toasts-arabic-light.png`), out of the window in right-to-left. **Decision:** `min-w-0` and `overflow-wrap: anywhere` on the message.
- **B6 (L) The Arabic letter-spacing reset also resets the wordmark's.** **Decision:** the wordmark and other Latin-only marks carry `lang="en"`, so the rule passes them by.
- **B7 (L) `ltrIslands` joins separate three-digit numbers** ("101 102 103", a phone-like run) into one island. **Decision:** digit groups are joined only by a no-break or thin space, or when a unit follows the whole run.
- **B8 (L) Plain Enter during an IME composition** still sends from the empty-level Otto line (`plan-view.html`) and first launch (`first-launch.ts`). **Decision:** the composer's guard (`isComposing`, keyCode 229) in both.
- **B9 (L) The templates guard reads only plain attributes and literal text.** `[title]="'Close'"`, `[attr.aria-label]="'…'"`, `{{ ok ? 'Saved' : 'Saving' }}` and custom inputs (`hint`, `confirmLabel`, `description`) pass. **Decision:** the guard also scans bound attributes and interpolations for quoted literals holding words, and the custom text inputs the shared controls take.
- **B10 (L) The smoke's Arabic audit lets real words through.** `LATIN_ALLOWED` holds `Home`, `Delete`, `Text`, `End`, `Up`, `Down`, `Space`, `Option`, `Desktop`, `Letter`, `Legal`; elements under 1 % opacity and all SVG are skipped; a word in any user-text element excuses it everywhere on the page. **Decision:** key names count only inside `kbd` or a left-to-right island, paper sizes only in the export dialog's select, hover-revealed controls have their `aria-label` and `title` audited, the section view's SVG text is audited, and user words excuse only the element they are in.
- **B11 (L) The Arabic smoke section does not switch back when it throws,** so the sections after it would run in Arabic. **Decision:** `try`/`finally` around it, restoring the language, the theme, the provider and the updater.
- **B12 (L, kept) What stays in the old language after a live switch:** toasts on screen, an open menu or dialog, the snap label until the pointer moves, thumbnails already drawn. **Decision:** accepted and written into `docs/i18n.md`.

## What was done

### A. Engine and main

- **A1.** `latinKey`: Shift on a `Key[A-Z]` key that writes ASCII punctuation returns the capital from `code` (Arabic 101's Shift+L, Z, D, F, C, V; Ctrl+Shift+Z redoes). Without Shift a Latin layout's punctuation on a letter key stays (AZERTY's comma on M). Tests in `keys.test.ts`.
- **A2.** `latinKey` returns a Latin-script letter (`\p{Script=Latin}`: ń, ł, Ż, ő, đ) as typed and remaps nothing while Ctrl and Alt are both held (AltGr). Tests for both, and that Ctrl alone or Alt alone still read the physical key. Confirmed no shortcut uses Ctrl+Alt.
- **A3.** (a) The lost model's stand-in is `Missing model` in core again (`plan.describe`, the glTF export's skipped list) and carries `missing: true`; core's `modelName` (and `I18n.modelName`) translates it where it is drawn: the plan's label, the Item tool's preview, Properties, the export drawings.
